# Structura Edit: план реализации

Актуализировано 8 сентября 2026 года после упрощения редактора. Приоритет —
минимальная рабочая основа, затем последовательное добавление операций.
Предыдущие [исследование](structura-edit-plan-2026-09-07.md) и
[отчёт прототипа](structura-edit-foundation-2026-09-08.md) остаются историческими.
Текущее поведение описано в [README редактора](../../../README.md).

## 1. Продукт и принятые решения

Открыть схему или сохранённый мир, свободно летать, выделить регион, выполнить
операцию, просмотреть результат, применить или отменить. Один блок — регион
1×1×1. Переключаемых инструментов и хотбара нет.

- PySide6, PyVistaQt и VTK; библиотека редактирования не зависит от GUI.
- Постоянная перспективная free camera, всегда noclip без коллизий.
- Основной экран — 3D и миникарта в правом верхнем углу.
- Нативные меню и небольшие панели параметров по запросу.
- Все операции проходят через общий API, Preview/Apply и Undo/Redo.
- Долгие вычисления и I/O выполняются вне GUI; очередь хранит актуальный запрос.
- Компоненты разделяются по ответственности и владеют своими ресурсами.
- Код без комментариев; решения и ограничения описываются в Markdown.
- Секциями и обновлениями управляет edit; render предоставляет геометрию с соседним контекстом.
- Мир читается из файлов. Запись только наших изменений остаётся будущим этапом,
  с ранее согласованным сравнением данных и выбором Cancel/Force при конфликте.

## 3. Интерфейс

### Камера и ввод

WASD и стрелки непрерывно перемещают камеру, пока удерживаются; вперёд — по
направлению взгляда. E/Space — вверх, Q — вниз, Shift ускоряет полёт. Колесо
меняет скорость полёта. ПКМ захватывает мышь только на время удержания и вращает
взгляд от позиции камеры. Орбитального вращения и изменения FOV при движении нет.
Короткий ПКМ также остаётся управлением камерой. Операции доступны через меню.
Потеря фокуса и отпускание клавиш прекращают движение. Поля ввода работают обычно.

### Выделение

1. ЛКМ выделяет блок как регион 1×1×1 и сохраняет его как якорь.
2. Удержание Shift показывает временную рамку до блока под курсором.
3. Перемещение курсора меняет временный 3D-регион; оба конечных блока включены.
4. Следующий ЛКМ фиксирует регион. Движение мыши после фиксации его не меняет.
5. Отпускание Shift до клика отменяет временную рамку, сохраняя предыдущее выделение.

Обычный клик начинает новое выделение. Меню Selection содержит координаты,
Select all, Clear, материалы и операции. Выделение доступно без выбора инструмента.

### Миникарта

Шесть подписанных проекций одновременно, в сетке 3×2. Изображения заполняют
ячейки целиком; внешних полей и промежутков нет. Виджет прижат к правому верхнему
углу 3D-вида. Он постоянно доступен и сворачивается в строку нажатием заголовка.
Кнопки закрытия и списка выбора проекции нет. Двойной клик перемещает камеру
в плоскости выбранной ячейки.

### Операции

В GUI доступны Fill, Replace, Erase, Move blocks и Duplicate. У перемещения
числовое смещение X/Y/Z и обычный Preview → Apply. Выделение после Move следует
за результатом. Формы остаются в Python API. Сложные ручки, размещение курсором,
кисти и новые режимы не входят в текущий минимум.

Параметры общих команд и их defaults заданы в одном месте. Изменение параметров
или выделения делает старый preview неприменимым. Enter в 3D применяет готовый
preview. Escape освобождает захват мыши, иначе отменяет preview или снимает
выделение. Панели закрываются после применения.

Следующие разделы содержат будущие возможности и не означают, что они уже
включены в GUI. Они не возвращают концепцию переключаемых инструментов.

## 4. Классический набор команд

| Группа | Команды и поведение |
|---|---|
| Выделение | Два угла; координаты; всё; снять; расширить/сжать; сдвинуть рамку; обрезать рамку по непустым блокам |
| Регион 1×1×1 | Те же Fill, Erase и Replace; отдельного инструмента блока нет |
| Область | Залить; очистить; заменить материал или точное состояние; изменить заданные свойства; переместить блоки; дублировать; повторить N раз по оси |
| Буфер обмена | Копировать; вырезать; вставить с preview; пропустить воздух; только в пустоту; повторная вставка; импортировать другую структуру; экспортировать выделение |
| Преобразования | Поворот на 90°; отражение по X/Y/Z; целочисленное увеличение; уменьшение с явно выбранным правилом |
| Формы | Кубоид, оболочка, стены, линия, сфера/эллипсоид, цилиндр; сплошной/полый вариант |
| Ландшафт | Кисть материала/удаления; покрытие поверхности; сглаживание высот с радиусом и силой |
| Связанные блоки | Заливка связанной области того же материала/состояния от клика, с границей и лимитом |
| Ограничители | Только выбранные типы/состояния; исключённые типы; существующие блоки; воздух; открытая поверхность; верхняя поверхность |
| Материал результата | Один блок или смесь блоков с весами; сохранить применимые свойства при замене материала |
| Анализ | Частоты материалов; группировка по ID или состояниям; доли; размеры; объём; число реально изменённых блоков |
| История и автоматизация | Undo/Redo; одна операция на жест/команду; Python через тот же движок |
| Мир | Открыть папку; измерение; координаты; радиус; ручной Refresh; отправить изменения |

Маска — общий фильтр операций, а не отдельный инструмент для каждой комбинации.
Выбор нескольких материалов из статистики может сразу задавать маску.
«Верхняя поверхность» и «любой открытый бок» остаются разными понятиями.
Маска отвечает, где менять, материал/смесь — чем менять. Простые условия
соединяются без собственного языка команд: выбранные типы И поверхность,
с исключениями. Активная маска видна в параметрах операции и сбрасывается одним действием.

Замена материала сохраняет совместимые свойства по явному параметру: например,
направление и половину лестницы. Нельзя переносить неподдерживаемое свойство или
неподходящее NBT на другой тип блока. Preview сообщает о таких преобразованиях.

После основного набора: связное выделение произвольной формы и вытягивание
плоской грани (Extrude). Они полезны, но требуют соответственно sparse-выделения
и определённого правила выбора поверхности. Не подменять их заливкой bounding box.

В основе каталога — документированные группы WorldEdit, а не предположение
о статистике популярности конкретных команд:
[выделение](https://worldedit.enginehub.org/en/latest/usage/regions/selections/),
[операции](https://worldedit.enginehub.org/en/latest/usage/regions/regionops/),
[clipboard](https://worldedit.enginehub.org/en/latest/usage/clipboard/),
[кисти](https://worldedit.enginehub.org/en/latest/usage/tools/brushes/).

## 5. Границы библиотек и модель данных

**Core:** форматы, проверка данных, чтение/запись участков мира, преобразование
координат, общие правила поворота blockstate и NBT. Для Java Anvil сначала
проверить адаптер к установленному Amulet 1.9.x на реальных файлах; собственный
контейнерный формат, сжатие и NBT-парсер не писать. Зависимость мира — optional extra.
Низкоуровневый адаптер должен сохранять неизвестные поля и не выполнять
неявную конверсию мира через другую версию блоков.

**Render:** стабильный API сборки части сцены с соседями; геометрия, материалы,
прозрачность, выбор владельца грани, проекции. Исправления контакта воды с землёй
проверить на закрытых и открытых гранях, стекле и частичных блоках. Общую проблему
геометрии не закреплять частным смещением всех поверхностей в edit.

**Edit:** ввод, выделение, операции, sparse-изменения,
clipboard, история, preview, конфликтный merge, расписание задач, GUI.
Разделить выросший `ui.py` по фактическим обязанностям; реестр команд хранит
название, описание, применимость, параметры и обработчик. Не строить универсальный
плагинный framework до появления реальной необходимости.

Форматы схем и мир предоставляют небольшому общему слою операции чтения блока,
обхода области и применения patch. Мир хранит глобальные целочисленные координаты
и dimension; локальные координаты меша и камеры не меняют адреса данных.
Для графики вдали от начала координат нужен локальный origin, иначе float32
теряет точность. Выделение может выходить за видимый участок.

Для ячейки различаются отсутствие данных/незагруженный чанк, явный воздух,
structure_void, полный blockstate и block-entity NBT. Незагруженная ячейка
не становится воздухом. Операция догружает нужные чанки до применения.
Сущности, биомы, ticks и остальные поля не следует объявлять частью обычной
замены блоков: их перенос и изменение имеют явную политику.

## 6. Подгрузка мира

1. Один раз сохранить путь и dimension; прочитать метаданные и доступные границы высоты.
2. Только по ручному Refresh вычислять набор нужных чанков/секций в выбранном
   радиусе вокруг камеры. Полёт не проверяет границы и не запускает загрузку.
3. При обновлении догружать новые части. Близкие части имеют приоритет;
   устаревшие задания исключаются из очереди.
4. Кэш ограничен памятью. Далёкие чистые части выгружаются; локальные правки
   живут отдельно и не исчезают при выгрузке геометрии.
5. Перестраивать меш изменённой части и затронутых соседей. Соседний контекст
   нужен для скрытых граней, соединений моделей, света и жидкостей.
6. Возвращать результаты с ключом источника, координатами и ревизией. Результат
   старой задачи не заменяет более новое состояние. Не пересылать копию всего мира на каждый клик.
7. Refresh перечитывает выбранный радиус с диска, обновляет фон и сохраняет
   локальный patch. Конфликтные позиции отмечаются; исходное «было» не забывается.
8. Мини-карта обновляет затронутые проекции из кэша; движение камеры меняет
   только маркер, а не запускает новый рендер карты.

Чтение активного сохранения показывает записанное на диск состояние. Оно не
видит ещё не сохранённую память игры. Первоначальные радиус и бюджет памяти
выбираются после замеров на тестовых мирах, а не из размера demo.

## 7. Запись только наших изменений

Для каждой изменённой позиции храним `before` и `after`: полный blockstate и
относящиеся к нему данные. Повторные действия объединяются. Если состояние
вернули к исходному, позиция исчезает из patch. Изменение данных сундука тоже
учитывается, даже если ID блока остался прежним.

Перед отправкой перечитываем только затронутые чанки и сравниваем каждую позицию:

| Текущее состояние | Действие |
|---|---|
| Совпадает с `before` | Применить `after` без вопроса |
| Уже совпадает с `after` | Считать выполненным, повторно не записывать |
| Отличается от обоих | Конфликт: показать количество и предложить отмену либо Force |

Изменения в остальных позициях из свежего чтения сохраняются. Логически patch
содержит только наши блоки; физически формат может потребовать повторной упаковки
секции, чанка или region-файла. Нельзя отправлять назад целиком старый snapshot.

При Force повторно читаем актуальные данные и заменяем только позиции текущего
patch. Если после показанного диалога появились новые обнаруженные конфликты,
показываем обновлённый конфликт, а не превращаем Force в бессрочное разрешение.
Без конфликтов дополнительного диалога нет.

Записи самого редактора сериализуются по источнику. Перед изменением делаем
восстановимую копию затронутых файлов или эквивалентный журнал; выбираем простой
путь, который реально поддерживает backend. Частичная ошибка сообщает фактически
записанные чанки; незаписанные изменения не теряются. Проверяем запись повторным
чтением, и только затем обновляем baseline соответствующих позиций.

Согласованный режим **не требует эксклюзивной блокировки Minecraft** и не
гарантирует атомарность между процессами. Force разрешает конфликт данных;
сравнение до/после уменьшает число потерь, но не исключает гонку с игрой.
Это ограничение описывается в документации, а не превращается в повторяющиеся
предупреждения при каждом сохранении. Обязательного мода или плагина в плане нет.

Undo после отправки в мир создаёт обратный patch к текущим данным и проходит
такую же проверку. Он не восстанавливает старую копию целого чанка поверх чужих правок.

## 8. Алгоритмические решения

- **Клик:** сейчас используется обход вокселей лучом DDA. Для точного попадания
  в лестницы и другие частичные модели добавить владельца грани в render;
  при необходимости оставить DDA как широкую фазу, а геометрию — как точную.
- **Move/Paste/Stack:** сначала получить неизменяемый источник, затем вычислить
  назначения. Перекрывающиеся области не должны затирать вход операции.
- **Будущее размещение:** геометрия ghost собирается один раз; движение обновляет общую
  матрицу его акторов. Он исключён из попаданий луча. Правильные blockstate,
  стыки и соседние грани пересобираются при закреплении преобразования; Enter
  применяет именно актуальный рассчитанный результат. Полный меш документа
  не строится на каждое движение мыши. Проверить готовый
  [PyVista affine widget](https://docs.pyvista.org/api/plotting/_autosummary/pyvista.plotter.add_affine_transform_widget)
  с ограничением целой сеткой и поворотами 90°, прежде чем писать свои осевые ручки.
  Текущий Move использует только числовое смещение и стандартный предпросмотр операции.
- **Rotate/Flip:** преобразовать координаты, направления, оси, угловые состояния,
  handedness и соответствующее NBT. Использовать таблицы/правила по семействам;
  не угадывать неизвестные свойства модовых блоков. Четыре поворота и два отражения
  должны возвращать исходные данные.
- **Scale:** сначала целочисленное увеличение и явно определённое уменьшение.
  Правило выбора блока, политика для doors/beds, сущностей и инвентарей входят
  в семантику операции. Произвольное дробное масштабирование откладывается.
- **Brush:** радиус и маска ограничивают область; один жест — одна отмена.
  Ограничить частоту нанесения и объединять повторное попадание в те же ячейки.
- **Связная заливка:** очередь обхода шести соседей, множество посещённых,
  граница области и бюджет. Нельзя считать незагруженное воздухом или молча
  применять недосчитанный результат при достижении лимита. Отмена прерывает обход.
- **Смесь материалов:** веса нормализуются; seed фиксируется в операции.
  Результат воспроизводим при preview/apply и не зависит от порядка обработки чанков.
- **Smooth:** первая версия работает с картой верхних высот, с заданными материалами
  и границей выделения. Сглаживание пещер и замкнутых 3D-объёмов — отдельный алгоритм.
- **Preview:** результат ревизии отдельно от документа; применение не вычисляет
  операцию второй раз. При изменении входов устаревший preview сбрасывается.

## 9. Приоритеты реализации

Следовать последнему решению пользователя: **основа раньше расширения набора
операций**. Не откладывать мир ради десятков новых кнопок и форм.

| Приоритет | Работа | Критерий |
|---|---|---|
| P0 · основа | Камера, обзор, непрерывный полёт, компактное управление; чтение мира и сущностей; Refresh и подгрузка радиуса | Открыть папку один раз, летать, видеть сохранённые блоки и сущности; Refresh сохраняет камеру |
| P1 · производительность | Меши секций с соседним контекстом, ограниченная рабочая область, измерение памяти и кадров | Полёт не запускает загрузки; локальные правки меняют только затронутые секции; F5 обновляет всю область |
| P2 · базовое редактирование | Развивать операции над регионом, маски, clipboard, Copy/Cut/Paste, импорт, Stack, Rotate/Flip | Одни операции для GUI и Python; корректные состояния/NBT, предсказуемый preview и одна отмена |
| P3 · запись мира | Patch, сравнение с актуальным диском, конфликтный диалог, Force, восстановление после ошибки | Записываются только наши изменённые блоки; сторонние правки других позиций сохраняются |
| P4 · расширенные операции | Кисти, линия и формы, смеси материалов, поверхность, Smooth высот, целочисленный Scale | Полезные операции с маской и бюджетом, воспроизводимость и отмена жеста |
| P5 · выпуск | Платформенные проверки, установка, примеры, подсказки, полные сбросы и пресеты | Сквозные сценарии воспроизводятся на целевых системах |

P0 работает в текущем окружении. Для P1 измерена стоимость окон 3×3, 5×5 и 7×7,
убраны повторные копии неизменённых данных, введены бюджеты. По последнему решению
пользователя загрузка запускается только явно; полёт не запускает фоновые задачи.
Независимые меши секций и сохранение неизменённых акторов реализованы. Хранятся
только части текущей области; LRU прошлых областей пока не нужен. F5 остаётся
полным перечитыванием и построением выбранного окна. Следующие измерения —
применение больших обновлений в GUI и память. Начальное окно — 3×3 чанка,
вертикальный радиус 32 блока.
Ближайший приоритет — качество небольшого прототипа до расширения операций:
[сценарий проверки и карта модулей](../../structura-edit-architecture.md).
Установка, документация и необходимые тесты выполняются в каждом этапе.
Работа с миром сейчас ограничена чтением, выделением и экспортом. Согласованный
режим best-effort записи остаётся в плане P3, а не объявляется готовым.

Первый сквозной сценарий уже проверен: схема → выделение → замена → preview →
apply → undo → save. Для мира проверен первый отрезок: открытие → полёт → Refresh
→ подгрузка → отображение сущностей. Правка → отправка patch → повторное чтение
добавляются после завершения соответствующих этапов.

## 10. Проверки и границы первого выпуска

Проверять результат независимым чтением, а не только тем же путём записи.
Нужны реальные маленькие миры разных поддержанных DataVersion и отдельно
синтетические пограничные случаи: отрицательные X/Z и Y, границы чанков/регионов,
внешние `.mcc`, разные способы сжатия, неизвестные NBT-поля, block entities,
частичная ошибка I/O, изменения между проверкой и записью.

Важные сценарии конфликтов: мир не менялся; изменился соседний блок; изменился
наш блок; совпало с желаемым результатом; изменилось только NBT; пользователь
отменил Force; данные изменились после диалога; Refresh при несохранённых правках;
Undo после успешной отправки. Не обещать через тесты отсутствие внешней гонки,
которую согласованная архитектура не исключает.

Отдельно проверять ввод и потерю фокуса, непрерывный полёт, отмену фоновой задачи,
отбрасывание устаревших результатов, точность камеры далеко от нуля, память после
долгого полёта. Для размещения проверить: отпускание ручки без commit, отмену Move
без изменения источника, источник поверх назначения, полёт без скачка ghost,
отсутствие попадания, смену оси, Enter при устаревшем расчёте, цифры в полях,
угол в пустоте и трекпад. Для текущего ввода проверять освобождение ПКМ,
натягивание региона по Shift, фиксацию кликом и отмену временной рамки отпусканием Shift.
Сброс проверяется после изменения маски, радиуса и параметров операции: defaults
восстановлены, старый preview не применим, блоки/история/выделение не изменены,
именованные пресеты сохранены. Сброс повторяем и после переназначения сочетаний.
Измерять холодную загрузку, время до первого изображения, задержку
локальной правки, обновление чанка, кадр навигации и пик памяти. Пределы и размеры
кэшей назначать по этим измерениям. Размер нашего кода и размер Qt/VTK установки
указывать отдельно.

В первый выпуск не входят: редактирование всех поколений Anvil без отдельной
проверки, запись Bedrock-миров, симуляция игры, генерация ещё не существующих
чанков, синхронная телепортация игрока, совместное редактирование через сервер,
свободный дробный Scale и 3D-сглаживание пещер. Эти пункты не представлены
неработающими кнопками. Расширение поддержки Litematic/Bedrock-схем планируется
через возможности core и отдельные проверки сохранности форматов.

Используемые основания: [Qt Main Window](https://doc.qt.io/qt-6/qmainwindow.html),
[PyVistaQt](https://qt.pyvista.org/usage.html),
[Amulet Core](https://github.com/Amulet-Team/Amulet-Core),
[Amulet world API](https://amulet-core.readthedocs.io/en/stable/api_reference/api/level/world.html).
Amulet 1.9.x используется для распаковки чанков и палитр. Узкий адаптер core читает
Anvil-файлы через rb: штатный region reader Amulet может открывать их через rb+
и изменять выравнивание файла даже при чтении. Запись в мир ещё не реализована.
