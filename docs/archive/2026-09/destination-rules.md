# Условия размещения

Выполнено 08.09.2026 после [осей и повторов](placement-stage.md).

Кнопка правила всегда видна в Paste и Repeat. Основная панель сохраняет две строки;
при ширине меньше 896 px размещение переходит на три строки, не меняя viewport.
Monocraft, квадратные рамки и сетка 4 px сохранены.

- Replace all: прежняя вставка.
- Keep existing: только воздух, включая пропуски в файле схематика.
- Only material: ID или полное состояние; выбор из загруженных материалов либо ввод ID мода.
- Copy air отдельно задаёт, копировать ли воздух источника; он также подчиняется условию назначения.

Условная вставка проходит Preview → Place. Показаны реальные изменения и счётчик
изменённых/пропущенных клеток. Adjust возвращает исходную сцену и готовый дух;
Cancel завершает размещение. No changes не создаёт историю и не расширяет документ.
Keep placing сохраняет весь захваченный буфер и правило; Take действует только первый раз.

## Устройство

DestinationRule не зависит от Qt или реестра модов. Core проверяет синтаксис состояния;
для ID сравнивается имя, для properties — полное каноническое состояние, как у маски Fill.
Paste/Stack используют plan_placement: API получает ChangeSet, GUI — PlacementPlan
с количеством совпадений и пропусков. Условия читают исходный снимок, включая пересечения
копий. Сравнения кэшируются по состоянию в пределах плана. Replace all обходит фильтрацию.
Бюджет проверяется до захвата и построения больших наборов.

Частичный Take удаляет только перенесённые клетки. Clipboard хранит исходные координаты
для каждого элемента отдельно от преобразованной позиции; поворот сохраняет их связь.
Заблокированные исходные клетки защищены от перекрывающих назначений. Защита через очередь
распространяется на зависимые перемещения за линейное время. Перекрывающийся частичный
перенос может остаться на месте целиком; preview показывает это явно.

Отсутствующие чанки и секции мира отклоняются до проверки материала. Неизвестное пространство
не считается воздухом. Схематик расширяется до принятых назначений; пустой результат не
расширяет bounds. NBT и Undo используют существующий ChangeSet.

PlacementReview управляет preview/adjust/apply. Геометрия и карты проходят общий ViewPipeline;
Place повторно использует показанные акторы. Сохранённый буфер входит в бюджет сцены до
создания акторов. Движение духа не проверяет всё назначение и не пересобирает меши:
правило вычисляется только по Preview в worker.

## Проверено

257 тестов pytest и Ruff проходят. API-проверки охватывают воздух и пропуски,
ID модов, точные состояния, пересечения Stack, повёрнутый частичный Take, цепочки
защищённых клеток, отрицательное расширение, отсутствующие чанки/секции, NBT и Undo/Redo.
Native smoke_destination_rules проверяет диалог, отмену, точный preview, повтор и камеру;
smoke_placement_tools проверяет прежний сценарий осей и размещения. Запись — только
во временные файлы. Физический тачпад и понимание новичком требуют живой проверки.

Локальный замер после прогрева: медиана 7 подготовок 10 000 копий сундука.
Replace all — 38,8 мс; Keep existing — 38,5 мс; Only material без совпадений — 11,6 мс.
Это расчёт ChangeSet без геометрии и Apply, не FPS. Обновление позиции небольшого духа
в native Qt — около 0,10 мс без новых мешей.
