# Продолжение доработок — 11.09.2026

После [компактного хранения документа](improvement-storage-2026-09-10.md)
реализованы три задачи: поэтапная установка сцены, пакетная правка NBT и локальная
автономная сборка macOS. Исходные незакоммиченные изменения сохранены.

## Поэтапная установка сцены

Профиль предыдущего этапа показал длинный вызов замены VTK-геометрии в GUI.
Теперь новые секции создаются скрытыми, а прежняя сцена остаётся видимой до
принятия целого результата. Между порциями работа возвращается в очередь Qt.
Целевое время порции — 6 мс; один неделимый вызов создания секции может занять
больше. Отмена запроса, reset, ошибка и закрытие окна освобождают временные
акторы. Ревизия и доступность Apply обновляются после завершения установки.

Синтетическая постройка: 24 этажа, 28 800 блоков, 57 625 затронутых клеток;
видимое окно, viewport 1104×660, Python 3.9.6 / macOS 26.6.2 arm64.
До изменения — два прогона с компактным документом, после — один прогон:

| Этап | Максимальный разрыв GUI-таймера до, мс | После, мс | Полное время после, с |
|---|---:|---:|---:|
| Open | 126 / 142 | 89 | 4,66 |
| Take start | 90 / 78 | 81 | 2,65 |
| Take Review | 323 / 337 | 217 | 9,85 |
| Take Apply | 578 / 247 | 568 | 6,78 |
| Save | 200 / 294 | 238 | 4,22 |
| Undo | 534 / 508 | 574 | 8,84 |
| Redo | 461 / 396 | 429 | 8,10 |

Это уменьшение измеренной паузы Review, а не доказательство ускорения каждого
этапа. Десериализация больших Python-объектов в потоке обмена продолжает удерживать
GIL; Apply и Undo всё ещё дают паузы порядка 0,5–0,6 секунды. Для следующего
этапа нужен отдельный контракт компактных результатов worker вместо пересылки
крупной сессии. Простое добавление ещё одного Python-потока проблему не решает.

Выборочный пик суммы RSS GUI и worker — 1453 MiB против 1396/1445 MiB ранее.
Это сумма RSS с возможным двойным учётом общих страниц; она включает fixture и
проверки. Новая и старая геометрия временно сосуществуют. Эти несколько прогонов
не задают p95 и не доказывают уменьшение памяти.

## Пакетный NBT

Objects → Find objects → **Edit field in all results…** собирает все результаты
запроса, независимо от открытой страницы. Действие ограничено 10 000 объектами
или меньшим лимитом сессии; при превышении требуется сузить поиск или выделение.
Зафиксированные строки привязаны к ревизии документа.

Пользователь указывает один существующий скалярный путь, например
`/Items/0/count`, и новое значение. Preview показывает изменённые, неизменные и
пропущенные объекты, причины пропусков и первые 24 примера. Наличие поля и
допустимость значения проверяются отдельно для каждого объекта; Byte, Short,
Int и прочие NBT-типы сохраняются. Неизвестные поля модов остаются прежними.
Внешние поля идентичности и координат защищены от этой массовой операции.

Apply использует общий ChangeSet и создаёт один шаг истории. Изменение ввода
сбрасывает preview и отбрасывает устаревшие ответы. Escape отменяет вычисление;
во время защищённого Apply закрытие диалога блокируется до завершения операции.
Ошибки worker видны также внутри диалога. GUI и Python API используют
`collect_nbt_targets` и `replace_nbt_values` из `nbt_batch.py`.

Попутно исправлен поиск блоков внутри CellSet: после проверки bounds требуется
принадлежность точному набору клеток. Отверстия произвольного выделения больше
не попадают в массовую правку через его охватывающий прямоугольник.

Проверены 150 контейнеров при странице из 64 строк, запуск со второй страницы,
типизированные значения, смешанные типы, переполнение, пропуски, экранированные
ключи, индексы списков/массивов, сущности с сохранением UUID, readonly, лимиты,
устаревшие результаты после Undo, единая история, Save/reload и отмена расчёта.

## macOS-приложение

`packaging/build_macos.py` создаёт отдельное окружение с зафиксированными
зависимостями и устанавливает свежие wheels трёх библиотек. PyInstaller собирает
`.app` с собственными Python 3.9.6, Qt 6.8.3, VTK 9.5.2, данными форматов,
Monocraft и примером. Ресурсы Minecraft в пакет не входят: проверка использует
цветной рендер с пустым каталогом ресурсов.

Проверка `--check-installation` выполняется самим собранным приложением и
возвращает результат JSON. Она открывает bundled demo, проверяет VTK-кадр и
проходит на временной структуре из 70 контейнеров Preview → Apply → Save/reload →
Undo. Фоновые процессы используют ранний `multiprocessing.freeze_support()`.
Скрипт создания ZIP выполняется только после успешной проверки приложения.

Готовый ZIP также распакован в `/private/tmp/structura-portable-20260911`.
Из этого каталога, с удалёнными `PYTHONPATH` и `PYTHONHOME`, повторно проверены
подпись и весь маршрут установки: результат `passed`, `frozen: true`, путь
bundled demo находится внутри перемещённого приложения. VTK-кадр проверен
отдельным framebuffer-снимком; обычный QWidget grab не захватывает native viewport.

Результат находится в `libs/structura-edit/dist/`: `.app`, ZIP и `build.json`
с хешами. Артефакты сборки игнорируются Git. Сборка для Apple Silicon имеет
ad hoc подпись; Developer ID и notarization для внешнего распространения ещё
не подготовлены. Проверена текущая macOS 26.6.2; отдельно не проверены macOS 12,
Intel Mac, Windows и Linux. Инструкции — в [packaging/README](../../../packaging/README.md).
