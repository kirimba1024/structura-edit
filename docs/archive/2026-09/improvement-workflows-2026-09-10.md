# Стена, этажи, перенос и восстановление — 10.09.2026

Продолжение [первого этапа](improvement-implementation-2026-09-10.md).
Существующие незакоммиченные изменения сохранены; коммит и публикация не выполнялись.
Проверены обычные действия редактора на воспроизводимой постройке с сундуком,
окнами и стойкой для брони. Это программно созданный пример, а не исследование
работы пользователей или запуск Minecraft.

## Исправления

**Отмена Planar и Paint во время расчёта.** Раньше Escape выключал режим, но
фоновая задача продолжала работать. Ответ Planar мог вновь включить инструмент,
изменить выделение и открыть Extrude; Paint мог показать уже отменённый preview.
Теперь выключение режима отменяет соответствующую задачу и инвалидирует её ответ.
Planar дополнительно проверяет активность режима при приёме результата. Для Paint
выход также убирает готовый preview. Защищённый Apply не прерывается.

Регрессии проверяют поздний ответ после отмены, повторное включение Planar и
сохранность документа. Native-сценарий посылает Escape через QTest в viewport
сразу после отправки обеих задач, затем дожидается завершения фоновой работы.

**Стоимость диагонального Paint.** Прежний алгоритм проверял весь ограничивающий
прямоугольник/параллелепипед отрезка. Даже тонкий мазок по диагонали большой области
мог упереться в бюджет. Воспроизведение: 256 существующих блоков на диагонали
области 256³, радиус 1, operation_limit=10 000. Два отсчёта завершались ошибкой
sampling budget, хотя тот же отрезок с частыми отсчётами помещался в лимит.

Теперь кандидаты перебираются по слоям вдоль самой длинной проекции отрезка.
В каждом слое диапазон параметра отрезка ограничивается радиусом, а по двум
остальным осям строится консервативная граница. Окончательное решение принимает
прежняя проверка расстояния до отрезка. Для длинного мазка работа растёт примерно
как длина × квадрат радиуса. Перебор потоковый; целый объём или поле расстояний
не создаётся. Предел кандидатов, число отсчётов, маски и семантика одного Undo сохранены.

Геометрический эталон отдельно проверяет шесть перестановок осей, обратный ход,
дробные и внешние точки, четыре радиуса, разрывы и разреженное выделение.

**Неявный Save после восстановления изменённого источника.** Если исходная
схематика уже изменена или удалена, GUI предлагал Save as, но `recovered.save()`
в Python всё равно писал по прежнему пути. Оба случая воспроизведены на временных
файлах. В восстановленной сессии теперь выставляется `requires_save_as`; Save без
пути сообщает об ошибке до записи. `recovered.save(new_path)` выбирает рабочий
файл, после успешной записи обычный Save снова доступен. Изменение исходника
определяется при восстановлении; это не новая система блокировки сторонних писателей.

## Сквозная проверка данных

Постройка 32×6×24 содержит каменные стены, два стеклянных блока, сундук с алмазами
и стойку для брони с UUID. Planar выделяет 157 клеток стены, обходя стекло и NBT.
Extrude добавляет слой наружу с отрицательным Z; Repeat создаёт ещё три этажа.
Take переносит все четыре этажа в отрицательные X/Y/Z.

Проверены NBT сундуков, четыре сущности, состояния блоков, размеры и origin до и
после Undo/Redo. Save → Undo Take → Save local draft → Recover local draft → Save
возвращает сохранённую постройку к состоянию до переноса. Восстановление само не
пишет источник; более ранняя история Undo отсутствует. Повторное чтение сравнивает
содержимое блоков и объектов, а не только их количество. Отдельно пройден тот же
цикл через API для NBT и Sponge; у Sponge проверяется сохранение offset.

Исходные файлы во всех случаях проверяются побайтово. Запись миров и Restore backup
проверяются существующими native-сценариями на временных мирах; личные миры не записывались.

## Измерения

Python 3.9.6, macOS 26.6.2 arm64. Одна стена 512×512×1, радиус 1, диагональ
от центра первого до центра последнего блока, по 9 повторов без tracemalloc.
Сравнение меняет только генератор кандидатов; остальные этапы Paint общие.
Наборы 1 534 изменённых клеток совпадают.

| Показатель | Прежний прямоугольник | Область вдоль мазка |
|---|---:|---:|
| Проверенные кандидаты | 262 153 | 2 558 |
| Медиана расчёта | 529,61 мс | 14,87 мс |
| Выборочный p95 | 537,35 мс | 17,33 мс |
| Дополнительный Python peak | 1,060 MiB | 1,101 MiB |

Ускорение медианы — 35,6 раза. p95 при девяти отсчётах совпадает с максимумом;
это небольшой локальный замер. Память измерена отдельным проходом после создания
документа и не включает его существующие объекты или native-выделения. Peak RSS
всего процесса benchmark — 100,89 MiB. Снижение памяти не заявляется.

Видимый GUI: окно 1104×720, viewport 1104×660 логических пикселей, framebuffer
2208×1320. Время включает подготовку, IPC и получение готовой сцены; это по одному
измерению каждой стадии, без объединения разных операций в p50/p95.

| Стадия | До готового результата | Максимальный интервал таймера GUI |
|---|---:|---:|
| Выделение стены | 28 мс | 28 мс |
| Extrude preview / Apply | 765 / 91 мс | 44 / 24 мс |
| Repeat preview / Apply | 2 073 / 791 мс | 66 / 75 мс |
| Take review / Apply | 2 819 / 2 070 мс | 105 / 139 мс |
| Save | 1 049 мс | 109 мс |
| Undo Take | 2 419 мс | 104 мс |
| Save local draft | 298 мс | 46 мс |
| Recover local draft | 1 843 мс | 92 мс |
| Save после восстановления | 606 мс | 69 мс |

Пик суммы RSS GUI и текущего worker — **910,33 MiB**, 391 выборка через `ps` с
паузой 20 мс между вызовами. Общие страницы могут учитываться дважды, краткие пики
могут быть пропущены. Таймер GUI с интервалом 16 мс фиксирует задержки event loop,
а не FPS или длительность отдельного обработчика. Полная работа ещё имеет паузы
до 139 мс; ускорение кисти не означает устранения задержек IPC и отрисовки.

Осмотрены отдельно изображения QWidget и framebuffer VTK. Захват QWidget на этом
Mac может давать чёрную область OpenGL или устаревшее содержимое; проверка сцены
опирается на framebuffer. После восстановления также проверяется отсутствие
preview-акторов и скрытие панели размещения. Физический тачпад не проверялся.
