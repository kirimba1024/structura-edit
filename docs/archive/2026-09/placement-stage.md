# Размещение: выполненный этап

Выполнено 08.09.2026 после среза по высоте. Все тексты GUI — на английском.

- [x] Оси X/Y/Z для духа: обычное перетаскивание, целочисленная привязка, Esc отменяет только drag; потеря фокуса прекращает drag.
- [x] Keep placing: повторные Place используют готовый буфер и геометрию; Take удаляет источник один раз; каждый Place — отдельный Undo.
- [x] Repeat selection: дополнительные копии, направление и зазор; один неизменяемый источник и один ChangeSet; общие проверки Paste/Stack.
- [x] Проверки API и native Qt: пересечения, NBT, расширение ±XYZ, Apply/Undo/Redo, срез, стабильные viewport/камера и отсутствие jobs при drag.
- [x] Замеры и обновление документации по фактическому результату.

Оси относятся к предпросмотру размещения блоков. Условия назначения выполнены
[следующим этапом](destination-rules.md). Группы сущностей и совместный перенос остаются в плане.

## Решения

Paste и Stack используют один планировщик целевых клеток. Повтор не применяет
каждую копию к промежуточному документу: перекрытия читают исходный Clipboard,
а при пересечении назначений выигрывает последняя копия. Лимиты проверяются
до выделения больших массивов. Расширение схематика вычисляется один раз.

Манипулятор рисуется в VTK overlay, без прозрачного QWidget. Ручки сохраняют
экранный размер. Перетаскивание работает в экранной проекции выбранной мировой оси;
ось, направленная почти в камеру, недоступна для drag, точное поле XYZ остаётся.
Обработчик принимает события до Navigation и освобождает управление на release,
Esc или потере фокуса. Объекты сцены и меши не создаются на каждом движении.
Порядок фильтров основан на [Qt QObject::installEventFilter](https://doc.qt.io/qt-6/qobject.html#installEventFilter).

## Интерфейс

Главные действия видны сразу: Place, Cancel, Keep placing, поворот. Options…
раскрывает один дополнительный уровень с точными полями, отражением и Copy air.
Это применение [progressive disclosure](https://www.nngroup.com/articles/progressive-disclosure/)
и [recognition rather than recall](https://www.nngroup.com/articles/recognition-and-recall/):
новичку не требуется запоминать сочетание клавиш для перемещения по высоте.

Подписанные оси и привязка опираются на практику
[Blockbench](https://blockbench.net/wiki/guides/blockbench-overview-tips/) и
[Axiom Gizmos](https://axiomdocs.moulberry.com/editor/gizmos.html).
Keep placing соответствует сценарию повторного размещения
[Axiom Clone](https://axiomdocs.moulberry.com/builder/buildertools/clone.html).
В Repeat задаётся зазор, а не абсолютный шаг: 0 означает вплотную; знак задаёт
понятное направление Up/Down/East/West/South/North с подписью мировой оси.

Сохраняется наша тема: Monocraft, квадратные рамки, контролы 28 px и сетка 4 px.
Базовая панель занимает 68 логических пикселей; раскрытая — 132. Кнопки заполняют
ячейки. После добавления условий область уже 896 px использует дополнительную строку.
Длинные значения не меняют размеры, viewport остаётся постоянным.
Принцип общей сетки согласуется с [Material keylines](https://m1.material.io/layout/metrics-keylines/);
стиль Material не переносится. Ручки учитывают различие логических координат Qt
и физических пикселей VTK на Retina по [Qt High DPI](https://doc.qt.io/qt-6.8/highdpi.html).
Короткие обязательные каноны находятся в корневом UI.md.

## Проверено

Общий прогон pytest: 240 проверок. Затем расширенный test_control_layout:
8 проверок, включая 2 новые для Repeat. Ruff проходит. Native smoke_placement_tools
проверяет оси, Escape, потерю фокуса, повторный Take, сохранение NBT, срез, расширение
в отрицательные координаты, смену параметров, отмену задачи и Undo/Redo.
smoke_gui проходит полный сценарий ввода, карт, выделения, изменения и сохранения.
Результаты записаны только во временные файлы, личный мир не сохранялся.

Контролы проверены при ширине 720/1104 px для размещения и 1104/1380 px для Repeat,
в том числе с координатами ±30 000 000. Визуально проверены снимки Retina.
Физический тачпад и понимание интерфейса начинающим пользователем требуют живой
проверки: синтетические Qt-события не подтверждают эти свойства.

На этом Mac 200 последовательных обновлений позиции небольшого духа: в среднем
0,097 мс на обновление без worker-заданий и новых мешей. Этот замер не включает
отрисовку кадра. Подготовка Stack из 10 000 копий одного сундука с NBT и ростом
схематика: медиана 46 мс за 5 прогонов API. Это расчёт ChangeSet, без мешей и Apply;
в интерфейсе он выполняется в worker. При Keep placing сохранённый дух входит
в общий лимит геометрии 192 МиБ вместе с итоговой сценой.
