# Инкрементальный world patch и карта среза

11 сентября 2026. Первые два пункта [уточнённой очереди](next-priorities-2026-09-11.md)
реализованы в текущем рабочем дереве. Изменения относятся к data path и покрытию
карты; организация GUI и семантика команд остаются прежними.

## World patch

`WorldChanges` готовит только затронутые ключи блоков и сущностей. Размер будущего
patch считается по чистому приросту ключей, поэтому замена существующего изменения
не расходует дополнительный лимит. Apply сначала записывает историю, затем
мутирует словари на месте. Ошибка записи или лимита сохраняет patch, видимое
состояние и redo-ветку. Устаревшее представление не может применить новую правку
к общей сессии с другой revision.

`WorldView` обновляет только видимые позиции из того же ChangeSet. Undo/Redo
передают дельту из истории; изменение в другом измерении или вне окна не требует
обхода всего patch. Переход секций сохраняет локальные затронутые координаты.
Open/Reload/Fork/Save сохраняют полную синхронизацию; устаревшее представление
перед шагом истории тоже сначала синхронизируется.

При изменении только блоков проекция сущностей сохраняется. Для операций с
сущностями пока используется прежняя полная проекция: она учитывает происхождение
записей и смену локальных ключей после Reload. Это ограничение оптимизации,
а не утверждение O(Δ) для любой операции редактора.

## Измерение

`tests/benchmark_world_patch.py`: один загруженный блок, остальные синтетические
изменения за пределами окна, настоящая SQLite-history. Пять повторов каждого
действия; ниже медианы в миллисекундах. Два прогона после изменения выполнены
отдельно от тестов и сборки. Полные данные — в
[evidence JSON](world-patch-delivery-2026-09-11.evidence.json).

| Накоплено клеток | Apply до | Apply после, два прогона | Undo до → после | Redo до → после |
|---:|---:|---:|---:|---:|
| 0 | 0,731 | 0,782 / 0,766 | 0,004 → 0,006–0,007 | 0,004 → 0,004 |
| 100 000 | 64,807 | 0,776 / 0,704 | 65,589 → 0,006–0,007 | 64,467 → 0,004 |
| 300 000 | 192,246 | 0,471 / 0,449 | 192,077 → 0,005–0,006 | 191,412 → 0,003–0,004 |
| 500 000 | 323,024 | 0,479 / 0,561 | 323,766 → 0,005–0,007 | 321,066 → 0,003–0,004 |

Это замер Python API, без GUI, Pipe и записи мира. Малые значения зависят от
шума и дисковой записи; существенный результат — отсутствие роста от размера
накопленного patch. Отдельный тест запрещает copy/iteration накопленных словарей
и полную синхронизацию во время Apply/Undo/Redo одного блока.

Fork при 500k всё ещё занимает 331–336 мс; pickle — 40–42 мс и 7 872 915 байт.
Данные benchmark используют общие immutable клетки, поэтому размер pickle
не моделирует произвольный большой NBT. Независимость fork и сериализованных
снимков сохранена. Следующий этап — удержание документа в worker и типизированный
lifecycle запросов с document/revision/task ID, включая отмену и поздние ответы.

## Карта

`map_spec` передаёт фактические bounds глубины для каждой проекции. `known_pixels`
проверяет чанки только внутри этого среза. Неизвестный чанк вне видимой глубины
больше не стирает полностью известный боковой пиксель. Пустой срез не публикуется
как известный воздух; чанки целиком вне окна не попадают в маску через отрицательные
индексы NumPy. Версия покрытия добавлена в ключ атласа, чтобы старые неверные
альфа-маски не использовались после обновления.

Регрессии покрывают четыре боковых вида, отражение осей, два origin, неизвестные
чанки внутри и вне среза, пустые срезы всех шести видов и сохранение/чтение тайлов.
