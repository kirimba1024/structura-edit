# Следующие приоритеты после проверки внешних предложений

11 сентября 2026. Предложения из чата сопоставлены с текущим рабочим деревом,
а не только с упомянутым в них коммитом 9 сентября и аудитом на 375 тестов.
На момент исходного аудита проверка core/edit и QEM: 953 passed. Предыдущий этап —
[отзывчивость Preview](preview-responsiveness-2026-09-11.md).
Пункты 1–2 реализованы: [world patch и карта](world-patch-delivery-2026-09-11.md).
Ограниченный этап пункта 3 тоже реализован: [lifecycle и снимок в worker](worker-lifecycle-2026-09-11.md).

Продолжение пунктов 3–4 выполнено: [компактные ответы, поиск и sparse-операции](data-path-delivery-2026-09-11.md).
Обычные блоковые Apply и один шаг Undo/Redo используют delta. Save/resize/entities/
переход через несколько записей сохраняют полный снимок. Поиск переиспользует один
запрос и общий ограниченный бюджет; Replace/Copy/palette/Top выбирают меньший обход,
Paste/Stack без Air считают реальные блоки. Ниже сохранены исходные критерии этапов;
не все оставшиеся полные снимки требуют немедленной замены.

## Что подтвердилось

| Предложение | Текущий код | Решение |
|---|---|---|
| Инкрементальный world patch | Подтверждён линейный рост до 323 мс за правку при 500k клеток | Исправлено: подготовка delta, запись history, локальное обновление видимых клеток; fork/IPC остаются отдельными затратами |
| Передача целой сессии | EditWorkflow теперь переиспользует один снимок worker; запросы несут task ID и версию документа | Входящий обмен сокращён; следующий шаг — delta в ответах Apply/History и нужные секции для render |
| Память и страницы Object Search | `17 * capacity` считает массивы индекса, но не рабочие маски; `flatnonzero` материализует все совпадения на каждой странице; CellSet дополнительно создаёт Python-список | Отдельный ограниченный бюджет результата и рабочей памяти; порционное извлечение страницы и повторное использование запроса |
| Sparse iteration и бюджеты | `replace` с обычным материалом обходит весь документ; Copy и план размещения ограничиваются bounding volume даже без копирования воздуха | Общий адаптивный обход; различать бюджет прочитанных, изменённых клеток и размер рендера |
| Cut и неизвестные чанки карты | Известность проверялась по всей глубине, хотя renderer использовал slab | Исправлено: фактические bounds и версия покрытия в ключе атласа |
| Resize без сдвига | `resize_document` копирует Structure и пересобирает ключи при нулевом offset | После измерений; сохранять независимость снимков и Undo |
| История Python recipe | `_recipe` использует fork с непостоянной History, для которой не действует вытеснение RAM-кэша | Ограниченная ветка вычисления без ненужной промежуточной истории; сначала определить поведение recipe, вызывающего undo/redo |
| Top/Overlay surface | Полный проход по `session.positions`, затем по выделению | Включить в работу над адаптивным обходом, не создавать отдельный движок фигур |
| Типы на границах | `EditPreview`/`DocumentUpdate` используют `object`; `_Delta.position` содержит локальную 3D-позицию, а в world patch — ключ из четырёх элементов | Развести координаты и типизировать границы при изменении соответствующего data path |
| Публичная поверхность ChangeSet/Clipboard | Корневой API экспортирует dataclass, содержащий внутренние клетки и дельты | Зафиксировать поддержанные поля и read-only inspection; не ломать существующие обращения массовым переименованием |
| CLI скрывает ImportError | `__main__.py` ловит весь ImportError при импорте GUI | Небольшая отдельная регрессия на ошибку внутри GUI и ожидаемое отсутствие optional dependency |

Воспроизведение карты: origin=(0,0,0), size=(16,4,32), известен только чанк (0,0),
cut=(15,3,15). Для South видимый slab равен `south:0:16` и полностью известен,
до исправления `known_pixels` возвращал 0 известных пикселей вместо 64. Второй чанк
находится вне slab. Новые регрессии проверяют альфу и сохранённые тайлы.

## Что уже сделано или требует уточнения

- **Очистка redo-хвоста исправлена.** `History.append` вставляет новую запись и
  удаляет недостижимые строки в одной SQLite-транзакции, затем обновляет entries/cache.
  `test_history_storage.py` проверяет 100 ветвлений и сохранение redo при ошибке БД.
  Для worker удаление redo-строк теперь откладывается до подтверждения снимка,
  чтобы потеря ответа Apply не повредила ещё показанную GUI-сессию.
- **Описанное расхождение Undo исправлено.** Меню и обработчик используют одну
  `history_action`. Для временного действия подпись явно меняется на `Cancel preview`,
  `Cancel placement` или `Cancel stroke`; Redo недоступен. Принцип «Undo только
  committed history» — возможное изменение продукта, а не исправление существующей
  неправильной подписи. Сохраняем текущий явный контракт.
- **Сборочные версии фиксируются.** Есть `packaging/macos-requirements.txt`,
  wheels из текущих исходников, версии и хеши в build manifest и installation check.
  Отдельные CI/constraints для разработки и минимальных платформ ещё полезны;
  workflow CI в просмотренном дереве edit не найден.
- **Headless import уже проверяется.** `test_session.py` запускает отдельный Python
  и проверяет отсутствие PySide6/pyvista/structura_render после импорта корневого API.
  AST-проверка прямых зависимостей выбранных модельных модулей дополнит этот контракт.
- **Преобразования уже имеют инвариантные проверки.** Есть `test_grid_transform.py`
  и `test_transform_cycles.py`, проверки полного цикла с NBT, сущностями, Save и Undo.
  Следующее расширение — registry-driven набор для поддержанных состояний и явных
  отказов; не требовать существования недопустимых в Minecraft пространственных состояний.
- **py.typed не удаляем по одному наличию `object`.** Сначала нужен отчёт одного
  type checker по намеренно выбранному публичному API. Маркер, API-совместимость и
  покрытие аннотациями рассматриваются вместе, без массового rename модулей.

## Порядок работы и критерии готовности

1. **Готово: маленькая правка большого world patch.** Benchmark на 0/100k/300k/500k
   накопленных клеток: Apply одного блока, Undo, Redo, Python API отдельно от GUI/IPC.
   Подготовить только затронутые ключи и изменение суммарного размера patch.
   Мутировать patch после успешной записи history; обновлять только видимые затронутые
   клетки. Сохранить независимость fork и опубликованных снимков. Проверить ошибки
   history/budget, Undo после Save, смену области/измерения, отрицательные координаты,
   сущности и соответствие эталонной полной синхронизации. Не объявлять весь GUI O(Δ):
   пересылка сессии и fork остаются отдельными затратами.
2. **Готово: регрессия cut/missing chunks.** Передать фактические bounds slab в map spec;
   проверять известность только внутри slab. Покрыть четыре боковых вида, отражение
   осей, пустой slab, неизвестное внутри и вне среза, отрицательный origin и кэш.
3. **Базовый этап готов: документ в worker.** Реализован ограниченный вариант одного открытого документа:
   `{document_id, revision, task_id, command, args}` и подтверждённые изменения обратно.
   Определить поведение при Cancel, перезапуске worker, устаревшем progress/result,
   Save, смене документа и ошибке команды. Сравнить bytes/time/RSS с текущим Pipe.
   Сохранить GUI/API на общих операциях и не превращать registry в plugin framework.
   Запросы и ответы должны быть типизированными значениями, а не новым набором
   строковых kind и произвольных dict. Сначала описать общий lifecycle для
   jobs/tasks/runner/workflow и правила принятия progress/result, затем переносить
   view/world/search на этот контракт. Различать идентичность документа, ревизию
   данных и версию входных параметров; один общий счётчик их не заменяет.
   Девять команд EditWorkflow получили отдельные типы; все сообщения Pipe — task ID.
   Отмена, потеря ответа и частичный сбой истории проверены. В обратном направлении
   Apply/History/Save ещё передают полный снимок; следующим отдельным шагом определить
   подтверждённую delta без повторного применения операции в GUI и без потери
   независимости опубликованных снимков. Legacy TaskCall и payload пока типизированы
   частично; strict mypy ограничен новыми protocol/worker_document.
4. **Поиск и sparse-операции.** Измерять `minecraft:` → Next → Next → Next,
   миллионы совпадений и CellSet; учитывать полную рабочую память. Общий итератор
   выбирает меньший обход, но не подменяет неизвестные клетки воздухом. Размещение
   без Air считает фактические клетки; лимиты будущей сцены проверяются отдельно.
5. **Контракты и инструменты качества.** Типы LocalPosition/WorldBlockKey,
   ChangeSet/preview/task boundary и небольшой набор domain errors при соответствующих
   изменениях. Один type checker, целевая проверка зависимостей, затем CI. Расширять
   общий расчёт доступности команд от существующей `history_action` при найденных
   расхождениях. Версию и обработку CLI ошибок исправлять небольшими самостоятельными
   изменениями.

Последовательностные тесты добавлять к шагам 1 и 3: Apply/Undo/Redo/Save/Reload,
Cancel/late result/reopen/failure/retry. Сравнивать с простой эталонной моделью после
каждого шага. Для текущего UX проверять cursor±1 только когда `ActionState.action`
равен undo/redo; явная отмена временного действия историю не меняет. Hypothesis
полезен при необходимости генерировать сложные последовательности, но не обязателен
для первой регрессии.

Детерминированный порядок определить на уровне API: запрос и страницы одного индекса
стабильны, одинаковые операции дают одинаковый результат. Не добавлять `sorted` на
каждый проход по миллионам клеток без оценки стоимости. Если нужен канонический
порядок, создавать его один раз при построении индекса/экспорте.

Большое перемещение файлов, глобальное форматирование и новый слой архитектуры
не являются ближайшей задачей. Ruff I/B/UP и format вводить отдельным проверяемым
этапом, чтобы не смешивать механический diff с исправлением поведения. Правила
комментариев и объяснений сохраняются из корневого AGENTS.md; этот документ их не меняет.

## Уточнения после дополнительного совета о lifecycle

- Единый расчёт capabilities развивать от существующих action-state контрактов:
  меню и обработчик должны принимать одно решение. Проверять переходы
  preview/input change/late result и placement/repeat/map, включая отказ запуска
  worker и повтор задачи. Количество модулей и тестов не служит критерием готовности.
- `CodeVersion.check` действительно обходит Python-файлы перед задачей. Измерить
  цену отдельно в editable и frozen-сборке; сохранить защиту от смешанных версий,
  пока не определён безопасный контракт разработки и перезапуска.
- Фиксированные wheels macOS не доказывают совместимость минимальных зависимостей
  standalone-пакета. README требует текущий core и изменения render после 0.8.1,
  metadata допускает более ранний код. Проверить установку вне workspace и связать
  минимальные версии с выпущенными API, не назначать несуществующие версии.
- Перед расширением lifecycle отслеживать число самостоятельных проверок
  актуальности и доступности команд, а также файлы, затронутые одной командой.
  Общий контракт оправдан сокращением этих расхождений, а не новым слоем сам по себе.
- Архивные документы остаются историей; текущие требования задают корневые правила,
  DEVELOPMENT, актуальная очередь и архитектура. Новая схема пакетов и изменение
  политики комментариев в этот этап не входят.

## Проверка дополнительного внешнего разбора

Разбор повторно сверён с рабочим деревом после data-path этапа, а не принят как
новые требования. Внешние обобщения об исследованиях coding agents отдельно не
проверялись и не использованы как основание изменений.

- **Lineage: замечание частично верно.** Прямой `EditorDocument.replace()` принимает
  две независимые ветки с одинаковыми ID/revision и разными state ID. Но оба production
  вызова replace — EditWorkflow и PlacementReview — предварительно проверяют захваченный
  token. Первый принятый результат увеличивает epoch и делает второй устаревшим.
  Проверены оба порядка доставки независимых ответов при executor, разрешающем два
  запроса: принят только первый, новый preview сохранён. Регрессия добавлена в
  `test_edit_workflow.py`. Утверждение «корректность держится только на одном worker»
  неверно для текущего GUI-маршрута. Самостоятельный контракт replace можно усилить
  обязательной проверкой ожидаемого исходного token внутри модели. Один state ID
  результата различает ветки, но сам по себе не доказывает происхождение от текущей.
  Второй механизм версий или параллельные worker ради этого не нужны.
- **Submit и Undo: описание устарело.** SubmitResult различает STARTED/BUSY/
  FAILED_TO_START; последнее значение ложно. Меню и handler истории используют
  history_action с явными Cancel preview/placement/stroke. Текущая типизация mypy
  ограничена тремя файлами worker, поэтому отсутствие проверки всех model/UI-границ
  остаётся актуальным, отсутствие type checker вообще — уже нет.
- **Общий запуск проверок: подтверждено.** Есть отдельные pytest, Ruff, mypy,
  native smoke и installation check; единого check_edit fast/native/full в дереве нет.
  Следующий небольшой tooling-шаг — исполняемый список обязательных проверок,
  остановка с ненулевым кодом при отказе/недостающем инструменте, изолированные
  временные данные, отчёт с реально выполненными сценариями. Fast содержит и Qt unit
  tests, поэтому его нельзя ошибочно называть headless; native не доказывает физический
  ввод. `.github/workflows` в workspace/edit не найден; наличие внешней CI не проверялось.
- **Capabilities: распределение правил подтверждено, новый конкретный сбой пока
  не установлен.** Расширять существующие чистые action-state правила по связанным
  командам и проверять их вместе с handlers. Не создавать сразу полную вторую модель
  GUI, которая сама станет ещё одним источником изменяемого состояния.
- **README: исправлено.** Команда подготовки полного test-набора теперь устанавливает
  `[gui,test]`; прежняя `[test]` не обеспечивала зависимости GUI-тестов.
- **CodeVersion: ограничение подтверждено.** Замена содержимого при сохранённых size
  и mtime_ns не обнаруживается. Это development guard от обычной смены исходников,
  а не проверка целостности или lineage документа; менять его на дорогой барьер
  без нового практического требования не планируется.
- Правила комментариев берутся из действующего AGENTS.md. Чужой аудит сам по себе
  их не изменяет; число комментариев, файлов и тестов не принимается за критерий
  качества. Для этого этапа важен проверенный порядок принятия результатов.
