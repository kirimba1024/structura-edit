# Компактная база документа — 10.09.2026

Продолжение [проверки строительных сценариев](improvement-workflows-2026-09-10.md).
Ускорены Take, Save и переходы истории за счёт сокращения повторных NBT-данных.
Существовавшие незакоммиченные изменения сохранены; коммит и публикация не выполнялись.

## Причина и изменение

Профиль 24-этажной постройки показал, что задержка Save возникает в том числе
в потоке обмена: `pickle.loads` результата занимал около 0,76 секунды, тогда как
обработчик результата GUI — около 3 мс. Фоновый Python-поток сам по себе не
гарантирует отзывчивость: сериализация, создание объектов и сборка мусора могут
удерживать GIL. В профиле Review также обнаружена установка VTK-геометрии около
0,47 секунды и повторная проверка ChangeSet около 0,18 секунды. Эти числа получены
с cProfile и используются для поиска причин, а не для сравнения скорости.

`Document` теперь создаёт компактную независимую копию Structure. Координаты и
индексы блоков остаются в `present`, NBT контейнеров — в `block_nbt`, сущности —
в `entities`. Из приватного `_root` исключены повторные списки блоков и сущностей;
`_block_records` при создании базы сохраняет лишь дополнительные поля клеток. Для обычного блока
больше не копируется отдельный CompoundTag с `pos` и `state` при каждом snapshot,
resize и обмене с worker. Входной Structure не изменяется.

Core writer уже собирает стандартные поля из актуальных индексов. Типы NBT,
дополнительные поля модов, корневые метаданные, палитры и содержимое контейнеров
сохранены. Внутреннее представление не вводит новый файловый формат и не меняет
формат черновиков или истории. Приватный `_root` снимка не является готовым
экспортом; для этого используются snapshot вместе с core writer или Save.

## Замеры

Python 3.9.6, macOS 26.6.2 arm64. Native Qt с видимым окном 1104×720, viewport
1104×660 логических пикселей. Постройка 32×144×24: 28 800 блоков, 24 сундука,
24 стойки для брони. Take в отрицательные координаты содержит 57 625 изменений
с учётом сущностей и размера. Все источники и записи временные.

Один исходный прогон и два повтора после изменения, без cProfile. Время стадии
включает подготовку, IPC и ожидание готовности сцены и карт.

| Стадия | До, с | После, с, два прогона |
|---|---:|---:|
| Open | 5,29 | 4,66 / 4,19 |
| Take: дух | 2,73 | 2,39 / 2,50 |
| Take: Review | 12,00 | 8,41 / 9,30 |
| Take: Apply | 7,68 | 5,96 / 6,07 |
| Save | 6,15 | 4,02 / 4,05 |
| Undo Take | 10,96 | 8,71 / 8,83 |
| Redo Take | 10,71 | 7,78 / 7,93 |
| Пик суммы RSS GUI + worker, MiB | 1658,70 | 1396,39 / 1445,36 |

В этих прогонах Save быстрее на 34–35%, применение Take — на 21–22%, Undo —
на 19–21%. Это локальное сравнение одного сценария, а не оценка p95 для всех
построек. Измерение RSS включает объекты fixture и проверки содержимого;
общие страницы GUI/worker могут учитываться дважды. Выборки через `ps` идут
каждые 20 мс плюс время запуска команды; короткий пик может быть пропущен.

Паузы GUI полностью не устранены. Максимальный интервал 16-мс таймера за весь
сценарий: 835 мс до и 578 / 508 мс после. Отдельные стадии не улучшились
монотонно: Take Apply дал 405 мс до и 578 / 247 мс после, Review —
321 мс до и 323 / 337 мс после. Следующие направления — объём сериализуемых
ChangeSet и установка VTK-акторов; они требуют отдельных изменений и замеров.

## Проверка данных и воспроизведение

Пять новых тестов проверяют сохранение обеих палитр и резервного поля palette,
дополнительных полей разных NBT-типов, независимое владение данными, размер
передаваемой базы обычных блоков, перенос через pickle и Undo после resize.
Отдельно проверено, что изменения актуальных полей Structure имеют приоритет
над исходным `_root`. Полный pytest core + edit: **787 passed**, 19 прежних
предупреждений. Ruff и diff --check проходят.

Прошли также native-сценарии `smoke_building_workflow` с видимым окном,
`smoke_formats` и `smoke_world_edit`: восстановление черновика и повторный Save,
открытие семи вариантов форматов, сохранение NBT и backup временного Java-мира,
Undo после Save world. Логи — `/private/tmp/structura-storage-*.log`.

Benchmark проверяет блоки, NBT и сущности после Take, Save с повторным чтением,
Undo и Redo; исходный файл остаётся побайтово неизменным. Осмотрен framebuffer
VTK. QWidget.grab на этом Mac даёт артефакты OpenGL и не использовался как
доказательство корректности сцены.

```bash
AMULET_LEVEL_CACHE_DIR=/private/tmp/structura-amulet-cache .venv-edit/bin/python libs/structura-edit/tests/benchmark_edit_workflow.py --visible
AMULET_LEVEL_CACHE_DIR=/private/tmp/structura-amulet-cache .venv-edit/bin/python libs/structura-edit/tests/benchmark_edit_workflow.py --visible --profile --output /private/tmp/structura-edit-profile
AMULET_LEVEL_CACHE_DIR=/private/tmp/structura-amulet-cache STRUCTURA_EDIT_DATA=/private/tmp/structura-storage-checks-data .venv-edit/bin/python -m pytest -q libs/structura-edit/tests libs/structura-core/tests
```

Native Qt запускается вне sandbox согласно DEVELOPMENT.md. `--floors` меняет
число этажей от 1 до 48; `--profile` сохраняет отдельные профили GUI и потока
обмена для каждой стадии. Для сравнения времени `--profile` следует убрать.
Числа и пути исходных результатов — [evidence JSON](improvement-storage-2026-09-10.evidence.json).
