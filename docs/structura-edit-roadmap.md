## Следующие задачи

| Приоритет | Задача | Граница и критерий |
|---|---|---|
| 1 | Согласованность команд и приёма async-результатов | Расширять существующий `history_action` по связанным действиям; ожидаемый исходный token проверять в модели. Матрица menu/handler и поздние ответы, без второго владельца состояния |
| 2 | Паузы больших Preview/resize | Профиль native GUI; проверить zero-offset resize и объём render snapshots. Независимость снимков и Undo обязательны; сложные worker-ответы остаются полными до измеримого выигрыша |
| 3 | Память длинных Python recipes | Ограничить промежуточную историю после определения поведения recipe с undo/redo. Итоговый diff и внешний эффект исключений не менять |
| 4 | Публичные контракты | Типы model/workflow, различие local/world coordinates, небольшие domain errors, точный CLI ImportError. Один источник версии; без массового rename или ломки API |
| 5 | Воспроизводимость вне workspace | Подключить существующую команду проверок к CI; сверить минимальные зависимости с реально выпущенными core/render. Проверить Windows/Linux и минимальную macOS отдельно |

В текущем GUI token/epoch отбрасывает второй независимый ответ после принятия первого;
корректность не держится только на одном worker. Сам `EditorDocument.replace` имеет
более слабый контракт — усиливать проверку исходной версии, а не добавлять новый счётчик.

Параллельные mutating workers, новый renderer, отдельный engine distribution,
plugin framework и массовая перегруппировка модулей сейчас не входят в очередь.
Новые инструменты добавляются после проверки базового сценария стена → этажи →
перенос → Save → Undo → recovery и ручного ввода физическим тачпадом.
