## 1. Продолжить устранение задержек во время работы

Закрыта подтверждённая часть CPU-карты: предварительные проекции сущностей,
отбор видимых, одно преобразование на вид; A/B на 512 сущностях сохранил все пиксели.
Pan/zoom не переписывает прежний атлас и не сбрасывает готовые тайлы; F5 с прежней
revision инвалидирует renderer. Это уменьшает работу карты при каждом движении
камеры, но не доказывает стабильный бюджет всего 3D-кадра.

- Следующий замер разделяет CPU-подготовку, IPC, установку VTK, первый GPU upload
  и обычный render. Проверить неделимые операции и связь задержек с акторами/материалами.
- Менять пакеты, batching или расписание только после A/B на одной сцене.
  Сохранять старое покрытие до готовности замены; не публиковать устаревшие jobs.
- Проверять кэши при возврате камеры, смене origin/палитры, edits и ресурсов:
  hit rate, лишние rebuild/decode, память и eviction. Не переносить устранённую
  стоимость в другой кадр или неограниченную очередь.
- Критерий — улучшение p99/p99.9/max без ухудшения изображения, управления и памяти.
  Средний FPS и более быстрая загрузка сами по себе не завершают этот шаг.

Уже проверено: SetSwapControl не поддерживается этим backend; отключение swap не
помогло, отключение OIT ухудшило tail; GC в контрольном полёте занимал до 0,27 мс.
Не повторять эти опыты без новой причины. Qt/Python не объявлять потолком без профиля.

## 2. После разблокировки получить эталон движения

- Повторить native navigation/capture с активным тестовым окном.
- Использовать мир A только для чтения, установленный HLOD v6 и прогретый кэш.
  Данные и записи тестов изолировать. Запускать проверки последовательно.
- Готовый `benchmark_overview.py --reuse --paths …` проверяет радиус 6 и viewport
  2760×1600, сохраняет raw samples, ресурсы и версии. Четыре маршрута уже заданы:
  лес, пещера, быстрое вращение, граница детализации; подтвердить их вид живьём.
- Измерять frame/render p50, p95, p99, p99.9, max, GUI gap, actors, geometry bytes
  и RSS. Профилирование проводить отдельным запуском; `--diagnostic` не является эталоном.
- Экран сообщает 120 Hz, таймер навигации — 16 мс (около 62 обновлений/с).
  Сначала оценить бюджет 16,67 мс, затем отдельно 8,33 мс и работу реального таймера.
  Не путать интервал таймера со стоимостью отрисовки.

Команда и ограничения — [verification](verification.md#замеры-по-задаче).

## 4. Проверить качество и взаимодействие целиком

Проверить живьём берёзовую листву, отсутствие наложенных поверхностей, spectator-пещеры
и F5, исходные текстуры при сильном zoom, entity Auto/Icons/Dots/Off, Cave map,
переиспользование превью, Move → ghost → Apply/Cancel/Undo и панели без resize 3D.
Для native OpenGL использовать framebuffer screenshot: QWidget.grab может дать чёрный
прямоугольник. Проверять также узкое окно, Retina и физический тачпад.

Дальний texture minification улучшать отдельным измеряемым экспериментом с mip-safe
sampling и alpha coverage. Обычный MipmapOn нынешнего atlas может вызвать bleeding.

## 5. Закрепить результат

Запустить соответствующие проверки по [verification](verification.md); `full` не считать
пройденным без native navigation. Сохранить компактные before/after и ограничения в архив,
обновить эту очередь. Последний локальный `fast` прошёл 1 213 тестов; проверки
геометрии панелей прошли Qt 6.8.3 и 6.10.2 на Mac. Последний удалённый edit CI
прошёл Linux/macOS; Windows ещё требует проверки фактической ширины окна в тесте
repeat-панели. Не заменять этот результат локальным прогоном.
Core 0.6.2/render 0.8.2 содержат обязательные API редактора; чистая установка
проверяет наличие модулей и совместимость версий. Матрица форматов core охватывает
30 поддерживаемых направлений; ограничения Bedrock, legacy и метаданных явно
описаны в [форматах core](../../structura-core/docs/formats.md).
Минимальная macOS, локальная упаковка и подпись
остаются отдельной границей проверок. Локальная arm64-упаковка из свежих
workspace wheels прошла bundled demo, worker/NBT/Save/Undo, overview/QEM и проверку
ad hoc подписи на macOS 26.6.2; это не notarization и не тест минимальной macOS.

Сохранить готовую основу: exact models, полигональный HLOD, отдельную map pyramid,
ограниченные кэши RAM/диска/GPU и подготовленные worker-пакеты VTK. Новый renderer,
greedy-everything и случайный FPS governor не вводить без доказанного узкого места.
Не обещать ноль лагов или готовность релиза без соответствующих проверок.
