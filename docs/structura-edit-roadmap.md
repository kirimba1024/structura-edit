# Следующие шаги Structura Edit

Одна текущая очередь; владельцы — [архитектура](structura-edit-architecture.md),
поведение — [workbench](workbench.md), результаты — [архив](archive/README.md).

## Рабочий контекст

Core, render, edit в `libs/` — отдельные
Git-репозитории. Подготовленная линия: core 0.6.3, render 0.8.3, edit 0.1.0a4.
Предыдущая выпущенная линия — [замеры](archive/2026-09/cubic-render-2026-09-12.json).
Перед работой проверить refs/status; читать [DEVELOPMENT.md](../../../DEVELOPMENT.md),
перед UI — [UI.md](../../../UI.md). Не менять исходники запущенного редактора.

Приоритет: правильная картинка и отзывчивость при полёте/работе с картой важнее
скорости первоначальной подготовки. Пользователь запретил computer use и локальные
native окна; визуально проверяет сам. Не повторять полные прогоны без новой причины.
Публикация разрешена для исходников; готовое приложение и бинарные ZIP не публиковать.

## Исправлено по проверке 12 сентября

- Кубические LOD: соседние прямоугольники объединяются без сдвига вершин; границы
  тайлов сохраняют разбивку. Старый QEM удалён, overview v7 и geometry cache v3
  автоматически отвергают несовместимые поколения.
- Cutout: back-face culling убирает совпадающие стороны травы, pointed dripstone
  и sculk vein. Листва сохраняет обе правильно ориентированные внутренние стороны.
  Bat на 1.21.1 получает свою текстуру вместо резервной.
- Выделение остаётся доступным при фоновой подготовке. Auto снова подгружает
  редактируемые блоки при наличии обзора. Иконка сущности на карте имеет приоритет
  перед блоком под ней; сдвиг origin переносит также entity bounds.
- Начальная загрузка включает установку сцены; управление разрешается после неё.
  Фоновый прогресс встроен в нижнюю панель, одна строка по приоритету задач.
- Превью вращается по времени; hover останавливает его, drag вручную меняет ракурс.
- Готовые карты принимаются при движении, затем уточняется последняя позиция.
  Совместимое покрытие сохраняется с ограничением памяти; Cave больше не отключает
  атлас остальных проекций. Пустые промежутки alpha-луча не смешивают пиксели.
- Точные секции привязаны к мировой сетке 64³, RAM хранит готовые пакеты; неизменные
  акторы переиспользуются после смены origin. CPU обзора готовит ограниченную очередь
  во время движения, установка GPU ждёт паузы.

## 1. Дальняя геометрия и устойчивый кадр

Компактная карта только top, раскрытая — шесть проекций/cave по
запросу. Overview v8 хранит текстуры до 16 texels/block и готовую пирамиду всего
сохранённого измерения; одна очередь читает её для миникарты и World. Повторный
Update переиспользует неизменные meshes/maps, включая совместимую геометрию v7.
Первый вход ждёт снимка. Выделение работает по показанным данным при смене области;
чтение иконок/каталогов больше не блокирует его.
Измерение только карты мира A: 2601 чанков, 31,8 с, 68,3 MiB PNG, пик RSS 95,9 MiB.
Чтение 25 тайлов: 11,7 ms холодное, медиана 0,017 ms из RAM. Это CPU/I/O, не FPS.

На границе рабочей области воспроизведена лишняя вертикальная стенка воды:
точный mesher считал соседний незагруженный чанк воздухом. Одноблочный внешний halo
убирает стенку, не расширяя редактируемую область; Undo/Redo и Save обновляют соседние
грани. Чтение halo мира A: 0,25 с, 1,57 MiB массивов. Core читает только нужные
region-заголовки. Визуально сверить полосу со скриншотом и переход detail/LOD всё ещё
нужно: геометрический тест не доказывает устранение всех эффектов прозрачности.
Визуальная приёмка новой карты и выбора остаётся у пользователя.

Текущий greedy meshing сохраняет исходную поверхность. Это исправляет кубичность,
но не является оптимальным по объёму дальним voxel LOD. Полный мир A (2601 чанков)
подготовился за 217,5 с; snapshot 480 MiB, подготовленная геометрия после сохранения quads — около 160–162 MiB.
Quad-пакеты сократили подготовку четырёх видов до 1,60–1,68 с и число пакетов
до 304–316. Исходные поверхности и snapshot не менялись.
Не объявлять эти CPU-результаты доказательством FPS новой версии.

Следующее алгоритмическое улучшение должно уменьшать дальний объём при сохранении
кубов, материалов и стыков. Сначала сравнить occupancy mipmaps/иерархическую сетку
с текущим точным эталоном, включая пещеры, навесы, тонкие объекты, листья и воду.
Обычный QEM и произвольное округление отдельных вершин не подходят. POP требует
отдельной проверки переходов и совместимости с нынешним VTK backend; не переносить
шейдерный renderer Voxy без обоснования. Источники — [world-view](world-view.md).

Локальный A/B: привязка 64³ к миру сократила повторную подготовку после перелёта
на 48 блоков с 7,26 до 5,19 с. Кандидат 32³ дал 2,95 с, но 676 пакетов вместо 205;
он отклонён из-за приоритета полёта. Дальше измерять отдельно IPC, установку акторов,
первый GPU upload и обычный render. При необходимости разделить гранулярность CPU
кэша и GPU batching, сохранив общий mesher и явные ограниченные интерфейсы.

## 2. Визуальная приёмка пользователя

После полного перезапуска проверить мир A: кубические деревья вдали и на стыках,
листву берёз, траву/dripstone/sculk, bat, выбор на 3D/2D, полёт в новую область и
возврат, начальную загрузку, нижний прогресс, плавность и drag превью. Кэш вручную
не удалять: несовместимые версии перестраиваются автоматически. Первый Build
занимает минуты, повторное чтение manifest не равно полной загрузке редактора.

Не запускать local native navigation/capture без новой явной просьбы пользователя.
После неё измерять p99/p99.9/max, GUI gap, actors и RSS по
[verification](verification.md#замеры-по-задаче), без параллельного профилирования.
Обнаруженные визуальные дефекты сначала воспроизводить на минимальной геометрии.

## 3. Большой Preview/Apply

После движения уменьшать GUI gap больших Preview/Apply, сохраняя NBT/entities,
Undo/Redo, Cancel и независимые snapshots. Запись и восстановление — только на
временных мирах. Core 0.6.3 меняет только выбор region-заголовков: матрица 30 поддерживаемых направлений и
ограничения остаются в [форматах core](../../structura-core/docs/formats.md).
